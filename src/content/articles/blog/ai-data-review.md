“不用于训练”不等于“没有任何数据保留”。在把工作文件、日志或客户资料交给 AI 前，应分别确认数据用途、保存方式、第三方环节及自己的授权范围，不能只依赖宣传页的一句话。

## 用当前产品的说明审查

[OpenAI 的 API 数据控制文档](https://developers.openai.com/api/docs/guides/your-data)区分不同数据用途与功能行为。某个 API 的默认政策，不能自动代表所有网页产品、第三方插件或自行搭建的代理服务。

如果通过第三方界面调用，还需检查该界面自身如何保存输入、输出和错误日志。服务提供方、应用维护方和公司内部系统可能是不同的数据处理主体，应把实际流向写出来。

## 先判断任务是否需要原始资料

很多问题只需要字段结构、少量样例或经过汇总的统计，无需整份原始名单。例如排查 CSV 格式错误，可以用虚构姓名保留相同列和编码特征；解释日志错误，可以只提供必要行并移除访问凭证。

但脱敏不能破坏要分析的关系。日期间隔、单位或异常值本身若是任务关键，应采用一致替换或明确说明变换规则。不要把失去意义的样本交给模型，再据此解释真实数据。

## 上传前做一张判断表

| 问题 | 未确认时怎么处理 |
| --- | --- |
| 我是否有权提供材料 | 先向资料负责人核实 |
| 是否含账户或访问凭证 | 删除或替换秘密 |
| 功能会保存多久、如何删除 | 查当前产品文档和设置 |
| 是否涉及外部工具 | 单独审查该工具访问范围 |

对公司受限资料，应遵守已批准的工具和组织政策。连接处于加密状态，也不能替代材料使用授权和数据处理约定。

## 输出同样需要管理

模型生成的摘要可能保留姓名、商业信息和文件片段，分享输出前还要检查一次。不要只保护上传文件，却把完整分析结果发到公开评论或开放链接。

验收包括输入范围可解释、功能设置有依据、结果分享对象明确，以及任务结束后按要求处理临时文件。对日志材料可使用[脱敏流程](/blog/privacy-log-redaction/)，对第三方集成则结合[授权范围检查](/blog/privacy-third-party-access/)逐项确认。
