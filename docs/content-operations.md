# 内容与数据维护规则

1. 品牌仅维护在 `src/data/airports.ts`。新记录必须是真实产品，填写官方来源、类别与核验日期；未知数据保留缺口，不能默认为已验证。
2. 方案需明确币种、总价、计费周期、流量重置与倍率。`verified` 仅用于已有证据的方案事实。不限流量不参与有限流量成本计算；年付与不限时方案不进入付费月度榜。
3. `tested` 只能在存在真实原始记录时使用，并扩展验证器关联记录。当前验证器会拒绝没有证据文件的 tested 声明。
4. 实测记录至少包含时间、网络、设备、客户端版本、套餐、节点、目标任务、失败样本及局限。不得声称当前品牌已完成实测。
5. Markdown 必须有唯一搜索意图、标题、描述、正文、真实发布与修改日期、来源和相关标签。标签决定自动相关文章，正文应包含上下文内链。
6. 实质修改后更新文章日期；专题和品牌内容修改同步维护配置中的日期逻辑。禁止把每次构建日期当成内容修改时间。
7. `npm run qa` 检查结构、链接与部分风险模式，不能自动证明事实真实。发布前人工核对当前来源。
8. 改变商业模式前更新披露。联盟链接需在可见页面说明，并添加 `rel="sponsored nofollow noopener"`，不能改变排名标准。
